# 相册持久索引与文件夹映射

## Goal

建立不依赖页面生命周期或全盘远端扫描的相册数据基础：识别 Android 媒体源文件夹、持久保存媒体与备份状态，并为传输、预览、后台任务和照片管理提供稳定契约。

## Dependencies

- 无前置子任务；这是整个任务树的首个实现任务。
- 后续 `photo-transfer-engine`、`photo-preview-gallery`、`photo-background-operations` 和 `photo-management-basics` 均依赖本任务的数据模型与迁移契约。

## Requirements

- Android MediaStore 查询必须包含 volume、ID、`RELATIVE_PATH`、文件名、MIME、大小、添加/修改/拍摄时间、尺寸、方向和视频时长等可用字段。
- 用户可以选择多个源文件夹，为每个源设置远端目标、启停状态、媒体类型以及“全部”或“仅新增”初始模式。
- 使用持久化数据库保存源文件夹、媒体资产、备份记录、远端资产和派生媒体状态；应用重启不得丢失已完成或失败状态。
- 日常发现只处理新增、变化、移动或消失的媒体；完整扫描仅用于初次导入、显式校验和修复。
- 远端路径保留源目录层级，并包含稳定的设备/来源边界；同名冲突不得静默覆盖。
- 旧 `YYYY/MM/DD` 备份可只读导入索引，不自动移动；显式迁移必须具有清单、可续跑和回滚信息。
- 向后续子任务暴露事务化队列、状态转换和分页查询接口，不在本任务内实现网络传输。

## Acceptance Criteria

- [x] 至少两个 Android 媒体文件夹可被单独配置，并解析出正确 `RELATIVE_PATH`。
- [x] 10,000 条以上媒体记录可持久保存、分页读取，且不会阻塞 Flutter UI isolate。
- [x] 应用重启后已发现、待处理、完成、失败状态保持一致，无需远端全盘扫描重建。
- [x] 新增、修改、移动和删除本地媒体能被增量协调，并产生确定的队列/异常状态。
- [x] 路径映射保留源文件夹层级；设备或源目录同名不会互相覆盖。
- [x] 旧日期目录可导入为 `RemoteAsset`，导入过程不修改任何原始文件。

## Notes

- 本任务属于核心 MVP。
- 本任务只建立数据和队列基础，不包含上传、缩略图或后台调度实现。
- 当前设置页允许多选来源并为新来源应用统一默认目标、媒体类型与初始模式；数据库契约已支持每来源独立字段，更细的逐来源编辑界面留在本任务后续 UI 验收。
