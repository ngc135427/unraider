# 相册后台备份与可观测性

## Goal

让日常相册备份不依赖进入相册页面，并让首次大批量备份、系统限制和失败原因对用户可见、可恢复。

## Dependencies

- 阻塞依赖：`photo-backup-foundation` 的持久队列，以及 `photo-transfer-engine` 的可暂停传输作业。
- `photo-management-basics` 的安全释放空间依赖本任务提供可信的已验证状态与最后成功信息。

## Requirements

- 使用 WorkManager 执行受网络、充电和电量约束的发现及增量备份。
- 首次全量导入或用户主动集中备份使用带常驻通知的前台执行模式。
- 进程被杀、设备重启、网络切换和应用升级后，队列可恢复且不会重复提交同一任务。
- 状态区分扫描、排队、上传、校验、完成、部分失败、暂停及权限/认证/空间/系统限制等阻塞原因。
- UI 与通知显示总体及单文件进度、实时吞吐、最近成功时间、失败原因和重试入口。
- OEM 电池限制、权限撤销和存储空间不足必须转化为可操作诊断。

## Acceptance Criteria

- [x] 不打开相册页面也能发现并备份新媒体，并遵守 Wi-Fi/充电策略。
- [x] 首次大批量备份可在前台集中模式持续运行并显示系统通知。
- [x] 进程终止、重启及网络中断后任务恢复，无重复成功记录或丢失失败记录。
- [x] UI 能明确显示各阶段数量、速度、最近成功时间和具体阻塞原因。
- [x] 单文件重试、全部重试、暂停和继续均可操作，且不会清空已完成状态。
