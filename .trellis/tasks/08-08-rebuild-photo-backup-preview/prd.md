# 重构相册备份与远端预览

## Goal

把 Unraider 现有相册从“进入页面后扫描并串行复制文件”的基础能力，重构为可长期可靠运行的照片/视频备份与远端图库：保留 Android 原始文件夹结构，支持 Unraider 已有的多种远端连接，显著改善增量备份吞吐、后台可靠性、缩略图加载和大图库浏览体验，并保持原始媒体可脱离 Unraider 直接访问。

## Background and confirmed facts

- 当前上传循环逐个处理媒体文件，见 `lib/pages/album_page.dart:567`。
- 所有 SFTP 传输经过单一串行队列，见 `lib/services/unraid_client.dart:1723`。
- 本地媒体默认以 1 MiB 分块经 MethodChannel 交给上传层，见 `lib/services/unraid_client.dart:1184`。
- 每处理一批 10 个文件后会强制重新扫描整个远端图库，见 `lib/pages/album_page.dart:627`。
- 待上传判断依赖完整本地列表与完整远端列表的路径差集，没有持久化备份清单，见 `lib/pages/album_utils.dart:42`。
- 远端网格当前通过 `fetchFileBytes()`读取完整原图作为缩略图；视频和大于 8 MiB 的图片没有缩略图，见 `lib/pages/album_widgets.dart:868`、`lib/pages/album_page.dart:23`。
- 远端缩略图只有进程内 64 项缓存，应用重启后失效，见 `lib/pages/album_page.dart:42`。
- 自动备份只在进入相册页面后触发，见 `lib/pages/album_page.dart:355`。
- 当前目标路径按修改日期生成 `YYYY/MM/DD`，没有使用 Android MediaStore 的 `RELATIVE_PATH` 保留源目录，见 `lib/pages/album_utils.dart:123`。
- 现有 Android 原生层已经包含 MediaStore 读取、本机缩略图和 SMBJ 远端读取能力，可作为原生流式上传及缩略图管线的基础。

## Requirements

### R1. Folder-preserving backup

- 读取并保存媒体的 Android 相对路径，以设备和源目录为边界映射到远端。
- 支持为多个媒体文件夹分别启用、暂停和配置目标目录。
- 原始文件名、目录结构、拍摄/修改时间和可用元数据不得因备份丢失。
- 目录冲突、同名文件、文件移动和设备重命名必须有明确、可恢复的规则。

### R2. Persistent incremental index

- 使用持久化索引记录本地媒体身份、源路径、目标、大小、时间、备份状态、失败原因和重试信息。
- 日常同步只处理新增或变化的媒体；完整远端扫描只能作为首次导入、手动校验或修复手段。
- 支持应用重启、网络中断和任务被系统终止后的安全续跑。

### R3. High-throughput transfer engine

- 本地 `content://` 媒体必须以原生流方式写入目标，避免每个小分块跨 Kotlin/Dart 往返。
- MVP 将 SMB 与 WebDAV 作为一级读写渠道，必须复用连接，并采用受控并发、临时文件、完成后原子重命名和失败重试。
- SFTP 保留为兼容兜底渠道，确保已有配置可以继续工作；不要求它与一级渠道达到完全相同的并发或断点续传能力，但必须遵守相同的数据安全和状态记录契约。
- 其他云盘或对象存储协议不进入 MVP；传输能力接口需允许后续新增适配器。
- 支持暂停、继续、取消、仅 Wi-Fi、仅充电和可配置并发/带宽策略。
- 不得因单个坏文件阻塞后续队列。

### R4. Thumbnail and preview pipeline

- 网格不得下载完整原图作为缩略图。
- 图片应具有至少一种网格缩略图；视频应具有封面帧和时长标识。
- 新上传媒体优先在本机生成 sidecar 缩略图并写入远端隐藏目录；历史远端媒体支持按需生成并持久缓存。
- 缩略图缓存必须落盘，并通过远端路径、大小、修改时间或等价版本标识失效。
- 点击项目后按需加载高清图；视频支持渐进播放或 Range 播放。

### R5. Large-library browsing

- 相册列表按需分页/虚拟化，只为可见区域及少量预取范围加载缩略图。
- 支持时间线、文件夹/相册视图、照片/视频筛选和快速跳转。
- 大图库的索引、分组和排序不得阻塞 Flutter UI isolate。

### R6. Background reliability and observability

- Android 后台备份使用系统调度机制运行，不依赖用户打开相册页面。
- 显示待备份、上传中、已完成、失败和需要用户处理的数量。
- 提供单文件与总体进度、实时吞吐、最近成功时间、失败原因及重试入口。
- 日志应区分扫描、排队、本地读取、网络上传、远端确认和缩略图阶段，并记录耗时及字节数。

### R7. Data safety and interoperability

- 原始媒体按普通文件保存，不要求通过数据库才能恢复。
- 上传中断不得留下被误认为完整文件的目标。
- 默认采用单向备份语义；远端删除不得静默删除手机原件。
- 支持对备份结果进行抽样或完整校验，并报告不一致。

### R8. Product benchmark coverage

- 研究并记录 Immich、MT Photos、Synology Photos、飞牛私有云相册、Nextcloud Photos/Memories/Les Pas 的备份、目录、预览、后台、搜索、共享和数据安全能力。
- 区分 MVP 必须实现、后续增强和明确不做的能力，避免把完整照片管理服务器一次性搬进客户端。

### R9. Benchmark-informed product behavior

- 首次设置提供“备份全部”和“从现在开始仅备份新增”两种明确模式。
- 备份状态区分扫描、排队、上传、校验、完成、部分失败、暂停及阻塞原因，不使用单一模糊进度。
- 提供适合首次大批量导入的前台集中备份模式，以及适合日常使用的受系统约束后台模式。
- 物理文件夹、时间线和逻辑相册是三种不同视图；逻辑相册不得复制原始文件。
- 备份状态在本地与远端项目网格中可见，用户可以区分仅本地、处理中、已验证和异常媒体。
- “释放手机空间”只能在远端原件已验证后提供，必须先展示将删除的项目和可释放容量。
- 基础搜索至少覆盖文件名、目录、日期和媒体类型；人物、语义、OCR、相似图片和地图作为独立可选阶段。
- 元数据、缩略图和转码应能重建；原始文件恢复不得依赖这些派生数据。

### R10. Pure-client baseline with optional NAS helper

- 纯客户端核心是强制能力：不部署任何服务时，源文件夹发现、增量备份、文件夹/时间线浏览、新上传媒体 sidecar 缩略图及本地磁盘缓存必须可用。
- 首期架构允许提供可选的 Unraid 轻量助手，用于历史远端图库批量索引、服务端缩略图/视频封面和哈希校验，并为后续兼容转码与 AI 能力提供扩展点。
- 助手不得成为定位、读取或恢复原始文件的必要条件；其未安装、离线或版本不兼容时，客户端必须明确提示并降级到纯客户端能力。
- 助手生成的索引、缩略图、转码和搜索数据均视为可重建派生数据。

### R11. MVP product boundary

- 当前 MVP 聚焦文件夹保持备份、持久化增量状态、高吞吐传输、可靠后台执行、缩略图/视频封面、时间线与文件夹浏览，以及逻辑相册、基础筛选/搜索、重复项复核和安全释放空间。
- 非 MVP 能力记录在下方任务地图和范围排除项中，作为独立后续子任务，不阻塞核心交付。
- 核心数据模型和可选助手协议需保留稳定扩展点，但 MVP 不为尚未实现的高级功能增加阻塞依赖。

详细产品矩阵和功能分级见 `research/product-benchmark.md`。

## Delivery task map

### Core MVP children

- `photo-backup-foundation`：持久索引、MediaStore 相对路径、文件夹映射与迁移；无前置依赖，首先实施。
- `photo-transfer-engine`：SMB/WebDAV/SFTP 统一安全传输；依赖 foundation。
- `photo-preview-gallery`：缩略图、视频封面、磁盘缓存和大图库浏览；依赖 foundation，并与 transfer 集成 sidecar 上传。
- `photo-background-operations`：WorkManager、前台集中备份、恢复与可观测性；依赖 foundation 和 transfer。
- `photo-management-basics`：逻辑相册、基础搜索、重复项复核和安全释放空间；依赖 foundation、preview 和 background 的已验证状态。
- `photo-nas-helper`：历史图库索引与派生媒体加速；依赖 foundation 和 preview，但不得成为任何纯客户端核心子任务的运行依赖。

### Follow-up children

- `photo-intelligence`：人物、场景、OCR、语义搜索与地图；依赖 management 和 helper。
- `photo-sharing`：共享相册、协作和链接；依赖 management，并需独立身份/权限设计。
- `photo-video-transcoding`：兼容转码与播放协商；依赖 helper 和 preview。

## Acceptance Criteria

- [ ] 用户可选择至少两个 Android 媒体文件夹，并在远端看到保留层级的对应目录。
- [ ] 已成功备份的媒体在应用重启后不会通过全盘远端扫描才能确认状态。
- [ ] 上传中断后可继续处理队列，不产生被标记为成功的截断文件。
- [ ] 同一目标允许受控并发上传，单个失败文件不会阻塞其他文件。
- [ ] SMB 与 WebDAV 均可完成原生流式上传、临时文件写入、完成校验和安全提交；SFTP 旧配置仍可作为兼容路径完成备份。
- [ ] UI 根据渠道能力显示可用功能，不把缺少原子移动、ETag 或断点续传误报为已支持。
- [ ] 相册网格加载只请求缩略图，不因原图超过 8 MiB 而缺失预览。
- [ ] 视频在网格中显示封面帧，进入详情后可播放。
- [ ] 缩略图在应用重启后仍可命中磁盘缓存，并在原文件版本变化后失效。
- [ ] 后台任务无需进入相册页面即可发现并备份新媒体，且遵守网络/充电约束。
- [ ] 用户能够看到总体进度、当前速度、失败项及可操作的重试状态。
- [ ] 首次设置可选择“全部”或“仅新增”，并能在不清空已完成状态的情况下继续备份。
- [ ] 时间线和文件夹视图引用同一份原始媒体，创建逻辑相册不会复制文件。
- [ ] 在执行释放手机空间前，系统只选择远端已验证媒体并提供复核页面。
- [ ] 未部署 NAS 助手时，文件夹保持备份、增量状态、时间线/文件夹浏览、新上传媒体缩略图和磁盘缓存仍可完整工作。
- [ ] NAS 助手不可用时不会阻断原件备份或读取，界面能显示降级原因并允许稍后重试助手任务。
- [ ] 各核心子任务可按任务地图独立验收；父任务最终集成验证覆盖“无助手纯客户端”和“启用助手加速”两条路径。
- [ ] 设计文档包含竞品能力矩阵、MVP 边界、数据模型、传输状态机和迁移/回滚方案。

## Out of scope for core MVP

- 人脸识别、对象/场景识别、OCR、自然语言/语义搜索和地图聚类。
- 多人协作相册、公开分享链接和服务端兼容转码。
- 将远端删除同步回手机，或把双向同步等同于备份。
